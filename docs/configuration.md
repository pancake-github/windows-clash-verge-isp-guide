# 配置字段与操作说明

## 三个配置部分如何配合

`proxies` 保存节点的协议、服务器与认证信息；`proxy-groups` 为节点提供手动选择入口；`rules` 决定流量交给哪个节点或组。完整示例同时提供三个部分，不能只填用户名和密码后就把空组、空规则当作完整的规则模式配置。

`select` 表示手动选择，不会按延迟自动切换。组中只包含 ISP 节点，因此不会在 ISP 不可用时自动转成直连或前置节点，避免误把其他出口当作 ISP。

## DNS 由谁管理

Clash Verge Rev 会把基础设置、选中订阅以及扩展配置或脚本合成为运行配置。DNS 覆写启用时，应用可以接管 DNS 字段；若脚本又写同一字段，最终采用应用所管理的值。具体范围取决于软件版本及当前设置。[官方实现](https://github.com/clash-verge-rev/clash-verge-rev/blob/dev/src-tauri/src/enhance/mod.rs)

本仓库选择一条明确路径：**在新 ISP 配置中写 DNS，并关闭该配置对应的应用 DNS 覆写**。不要同时让界面和脚本争用同一字段。已有全局脚本维护的 VPN 域名策略继续保留，示例采用 blacklist 模式以方便追加真实解析例外。

示例省略 `dns.listen`，不新增本机 DNS 服务监听端口；内核仍可为代理连接执行内部解析。示例也不指定系统代理端口、控制接口或 TUN 开关，这些继续由应用当前设置管理。

## 已有 VPN 的三个配置层

企业、校园或科研平台的 VPN 环境应按已有可用配置保留以下内容：

1. **流量规则**：将已确认的精确服务域名和 IP 的 `DIRECT` 规则放在 `GEOIP` 和 `MATCH` 前面。
2. **DNS 规则**：需要专用 DNS 的域名继续使用 `nameserver-policy`，使用 Fake-IP 时按原约定保留过滤例外。
3. **操作系统及 TUN 路由**：保留已有 VPN 入口排除、接口选择和系统代理绕过设置。YAML 中的一条 `DIRECT` 不能代替所有系统路由设置。

不要为方便而把未知的大网段一律直连，也不要删除原有全局脚本。公开教程不包含真实机构的服务地址；仅在自己的本地副本中填写已确认的数据。

## 规则模式和全局模式

本仓库默认说明**规则模式**：局域网和国内目标直连，其他目标走 ISP。

全局模式用于你明确希望所有受代理接管的流量走同一出口的场景。链式方案在全局组中要选择 ISP 节点或 ISP 出口组；选择前置组只会得到前置出口。全局模式下不能依赖上述规则完成 VPN 分流。

系统代理只影响遵循系统代理的应用。TUN 用于更广泛的流量接管，它是单独的需求选择，不是 `dialer-proxy` 生效的前提，也不应作为完成教程时必须同时打开的按钮。

## 本地文件与订阅更新

本地 YAML 没有远程拉取地址，修改后保存，再在需要时重新加载或启用该配置。远程订阅卡片的“更新”按钮用于拉取服务商内容；它不负责刷新独立本地文件中的 ISP 账号。

链式示例把前置节点放在同一个本地文件中，因此原远程订阅更新后，需要自行同步该节点的变化。若以后改用 `proxy-providers`，应单独配置订阅来源、加载方式和更新规则，并把含 token 的链接留在本地，不直接提交到仓库。

## 认证字段和特殊字符

代理用户名、密码与供应商网站的登录凭据可能不同。保留字符串引号；密码中含 `#`、冒号或引号时应按 YAML 规则转义。若使用代理 URI 导入，特殊字符还需要 URL 编码；本教程优先使用独立 YAML 字段，便于检查。

不要将 HTTP 代理端口填入 SOCKS5 节点，反之亦然。供应商写“HTTPS 代理”时，应进一步确认指的是转发 HTTPS 网站还是代理接入自身使用 TLS，再决定 `tls` 字段。

## 安全分享配置

日常文件可放入本机仓库的 `local/` 目录，该目录已被 `.gitignore` 排除。Git 忽略规则只对尚未跟踪的文件生效；提交前仍应检查实际暂存区。

教学示例中的 `DemoOnly` 字符串是明确的虚构值。不要把真实参数替换到已经被 Git 跟踪的 `examples/` 文件中再推送；建议先复制到 `local/`，在副本中编辑。
